En esta máquina se simula un escenario realista de compromiso de una aplicación web vulnerable. El objetivo es identificar vulnerabilidades, obtener acceso inicial al sistema y escalar privilegios hasta conseguir acceso completo a la máquina.

El vector principal de ataque se basa en la explotación de una vulnerabilidad de lectura arbitraria de archivos dentro de un CMS vulnerable.

## Explotación – CVE-2024-46987

Se identifica una vulnerabilidad de lectura arbitraria de archivos autenticada. Esta vulnerabilidad permite leer archivos del sistema, pero no listar directorios.
Descargamos el repositorio y lo ejecutamos en nuestro equipo obteniendo los diferente usuarios del sistema, entre los cuales destacan **trivia y william**

``python3 CVE-2024-46987.py -u http://facts.htb -l jorge -p jorge /etc/passwd``

## Obtención de credenciales SSH

Basándonos en la estructura típica de Linux, se intenta acceder al directorio `.ssh` del usuario trivia. y utilizamos el siguiente comando:
``python3 CVE-2024-46987.py -u http://facts.htb -l jorge -p jorge /home/trivia/.ssh/id_ed25519``. Obteniendo de esta manera la clave ssh del usuario trivia

<img width="773" height="168" alt="imagen" src="https://github.com/user-attachments/assets/72e804c1-9a07-4774-9bab-c518c9c137eb" />


Al intentar hacer login con la clave observamos que la clave cuante con un acpa de seguridfad añadida. 
Ya que es una clave privada protegida mediante passphrase, de tal manera que extraemos el hash de la clave ssh mediante la herramienta ssh2john
``ssh2john clave_trivia_ssh.txt > hash.txt``

Y posteriormente transformamos el hash en una clave de texto plano con la herramienta john the ripper obtenmiendo la passphrase **dragonballz**

## Escalada de privilegios

Una vez ya sabemos que binario podemos ejecutar como sudo, estudiamos dicho binario y observamos mediante el comando de ayuda que podemos modificar el directorio al que hace referencia a la hora de ejecutarse, de tal manera que podemos cargar un script en dicho directorio con una orden que no cree una shell y al hacerlo con privilegios sudo estos seran los derivados de la creaccion de dicha shell.
Esta opción permite cargar scripts Ruby personalizados, de manera que lo hacemos y ganamos acceso como root al sistema

## Conclusión

Esta máquina demuestra cómo una vulnerabilidad aparentemente limitada, como la lectura arbitraria de archivos, puede derivar en un compromiso completo del sistema cuando se combina con conocimiento del sistema operativo y técnicas de escalada de privilegios.

El ataque pone de manifiesto la importancia de proteger correctamente aplicaciones web autenticadas, gestionar adecuadamente credenciales y restringir privilegios sudo para evitar abusos de binarios del sistema.
